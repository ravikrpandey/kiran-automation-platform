# Hosting and storage decision notes

Verified 26 October 2026 from provider documentation. These notes support the approved demo architecture; they are not a claim that any provider account has been provisioned.

| Provider | Verified facts | Architectural consequence | Source |
|---|---|---|---|
| Render | A free web service sleeps after 15 minutes without inbound traffic and usually takes about a minute to wake. Its filesystem is ephemeral. Free instances are explicitly for testing/hobby/preview, not production. Free services cannot send outbound traffic on ports 25, 465 or 587. A Blueprint supports native `node` web services, `plan: free`, build/start commands, health checks, `envVars` with `sync: false`, and `autoDeployTrigger: off`. | Serve the built frontend and API from one Node service; never save leads, sessions or CVs on local disk. A free demo will be cold-started and should not be presented as always-on/production. Standard SMTP ports are blocked on this plan; later mail delivery must use a provider HTTP API, an allowed SMTP port (if supported by the provider), or a suitable paid host. | [Render Free services](https://render.com/docs/free); [Render Blueprint YAML reference](https://render.com/docs/blueprint-spec) |
| Aiven MySQL | The listed free plan has 1 CPU, 1 GB RAM and 1 GB storage on one node, may power off after a period of inactivity, and is described as suitable for small/prototype workloads rather than high-traffic production. MySQL TLS modes `VERIFY_CA` and `VERIFY_IDENTITY` require Aiven's project CA; Aiven documents downloading the CA from the service overview. | Suitable for a fresh-lead prototype, not an unreviewed production workload. Use TLS; keep the Aiven CA as a private runtime setting if identity/CA verification is selected. Monitor capacity and upgrade before business-critical use. | [Aiven Free MySQL](https://aiven.io/free-mysql-database); [Aiven TLS/SSL certificates](https://aiven.io/docs/platform/concepts/tls-ssl-certificates) |
| Cloudflare R2 | R2 supports S3-compatible presigned `GET`, `PUT`, `HEAD` and `DELETE` links from 1 second to 7 days. Presigned URLs are bearer tokens. Its S3 compatibility matrix explicitly marks the standard `x-amz-server-side-encryption` (SSE-S3/AES256) header unsupported on `PutObject`; R2 automatically encrypts objects and metadata at rest with AES-256 and uses TLS in transit. | Keep CVs in a private bucket; the application uploads server-to-server and uses short-lived authorized presigned `GET` URLs for administrators, so browser-upload CORS is not required. Do not send unsupported SSE-S3 headers. Verify private bucket settings and signed-download expiry before enabling career submissions. | [Cloudflare R2 presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/); [R2 S3 API compatibility](https://developers.cloudflare.com/r2/api/s3/api/); [R2 data security](https://developers.cloudflare.com/r2/reference/data-security/) |
| Supabase | Each Supabase project receives a PostgreSQL database; it is not a MySQL service. | Not selected because the user requested MySQL. Reconsider only if the user explicitly changes the database engine. | [Supabase Database overview](https://supabase.com/docs/guides/database/overview) |

## Deployment gates

Do not place provider credentials, MySQL CA material, bootstrap administrator secrets, storage keys or SMTP credentials in this repository. Render's `sync: false` entries are prompts for dashboard-supplied values, not stored secrets. Do not enable automatic deployment until the build, schema migration, health endpoint, forms, access controls and privacy content are reviewed.


## Render migration nuance

Render's official deployment docs state that `preDeployCommand` is available only for paid web services, private services and background workers; it is not available on the free web plan. Therefore the demo Blueprint must not depend on a pre-deploy migration hook. Do not mutate Aiven data during the build command. For the first fresh-database demo, run the reviewed, idempotent migrations from the server startup command with connection retries; for later production, move schema changes to a paid pre-deploy/release workflow after reviewing backwards-compatibility.

Source: [Render deploy command lifecycle](https://render.com/docs/deploys#pre-deploy-command); [Render's free-plan Blueprint example and migration note](https://render.com/docs/deploy-rails-8#creating-services-with-a-blueprint).
